# SPEKA

Спецификация RKS. Реализация следует этому документу. Если поведение расходится со SPEKA, верным считается документ, пока его явно не изменили.

## 1. Назначение

Локальный трекер для одной команды до 40 человек. Один проект. Два типа карточек на одном уровне: задача и баг. Вложенных эпиков и подзадач нет.

Вход по почте и паролю. Сессия живёт 30 дней. Все действия пишутся от вошедшего человека. Уже заведённым людям при первом запуске этой версии ставится пароль `tracker`.

## 2. Стек

- Клиент: Vue 3, Composition API (`script setup`), Vue Router, Vite.
- Сервер: Node.js, Express, REST JSON.
- Данные: PostgreSQL 16.
- Файлы карточек лежат на диске сервера, в базе только метаданные.

Каталог называется `rks_jira_nuxt`, но клиент — Vue 3, не Nuxt.

## 3. Интерфейс

Тёмная тема по умолчанию, есть светлая. Много пустого поля и тонкие границы. Колонки, тип карточки и метки различаются цветом обводки, без яркой заливки.

- Фон рабочей области темнее не бывает «почти чёрным»: спокойный серо-синий.
- Боковая панель чуть темнее области.
- Текст серый, вторичный текст ещё тише.
- Акцент: более светлый текст и лёгкая подложка у активного пункта. Колонки «Бэклог», «В работе», «Ревью» и «Готово» подписаны разными приглушёнными цветами. Задача и баг отличаются полосой слева. Метка — цветная обводка.
- Пустое состояние: контурный куб по центру и короткая подпись.
- Шрифт системный, размер около 13px. Заголовки страниц без крика.
- Названия разделов в боковой панели — мелкие прописные, как служебные подписи.

Боковая панель: логотип и «Наш трекер», список проектов, список команды. Клик по проекту открывает канбан. Сверху экрана переключатель Канбан / Бэклог / Роудмап. Панель скрывается кнопкой меню. Внизу — имя вошедшего, иконка справки, иконка темы и выход. Карточка открывается панелью справа.

При первом входе показывается крупная инструкция со схемой, куда нажимать. Шаги листаются стрелками. Снова открывается иконкой вопроса. Факт просмотра хранится в браузере.

Интерфейс рассчитан на ширину от 1100px. Уже этого доска листается по горизонтали.

## 4. Сущности

### Проект

Один. Ключ `TASK`. Номер карточки сквозной, ключ выглядит как `TASK-12`. Название проекта — «Наш трекер».

### Человек

Имя, почта, инициалы, пароль. Инициалы — первые буквы первых двух слов имени. На карточке показывается фамилия и инициалы. Почта уникальна. Человека с паролем можно добавить из списка команды. У задачи несколько исполнителей.

### Метка

Короткое имя, уникальное без учёта регистра. Цвета нет. Метку можно создать из карточки и снять с карточки.

### Спринт

Имя, цель, даты начала и конца, статус: `planned`, `active`, `closed`.

Активный спринт один. Закрытый снова не открывается. Удалить можно только запланированный: его карточки уходят в бэклог.

Закрытие активного спринта оставляет сделанные карточки в спринте, остальные снимает в бэклог.

### Карточка

| Поле | Правило |
| --- | --- |
| type | `task` или `bug` |
| title | 1–200 символов |
| description | обычный текст до 20 000 символов, не HTML |
| status | `todo`, `in_progress`, `review`, `done` |
| priority | `low`, `medium`, `high`, `critical`. По умолчанию `medium` |
| estimateHours | пусто или число от 0 до 999 |
| assignee | человек или никто |
| reporter | кто создал |
| sprint | спринт или бэклог |
| startDate, dueDate | даты или пусто. Начало не позже дедлайна |
| position | порядок внутри колонки и спринта |

Статус можно сменить на любой другой. Жёсткого маршрута нет.

Колонки доски, в этом порядке:

| status | Подпись |
| --- | --- |
| todo | Бэклог |
| in_progress | В работе |
| review | Ревью |
| done | Готово |

### Чеклист

Пункты одной плоской группы: текст и отметка. Порядок — порядок создания.

### Комментарий

Текст 1–5000 символов, автор, время. Удалить может любой.

### Файл

До 10 МБ, любое расширение. В интерфейсе файл скачивается. Удаление стирает и строку, и файл на диске.

### Списание времени

Часы больше 0 и не больше 24 за одну запись, короткая заметка, дата, автор. На карточке видна сумма списаний рядом с оценкой.

### История

Пишется при создании и при смене названия, типа, статуса, приоритета, исполнителя, спринта, оценки, дат, меток. Для описания хранится только факт правки, без старого и нового текста. Также пишутся добавление и удаление пункта чеклиста, файл и списание. Галочка чеклиста в историю не попадает. Комментарии живут своей лентой.

## 5. Доска

Показывает карточки одного среза: выбранный спринт, бэклог или все.

Карточку перетаскивают между колонками и внутри колонки. Пока включён поиск или фильтр, перетаскивание выключено, чтобы не ломать порядок скрытых карточек.

Новая карточка создаётся в колонке «Бэклог» текущего среза. Если открыты «все задачи», она попадает в бэклог. На экране бэклога слева очередь без спринта, справа спринты; карточка перетаскивается между ними.

Фильтры на клиенте: текст по ключу и названию, приоритет, метка, исполнитель.

На карточке в колонке сверху фамилии исполнителей, затем ключ, тип, название, приоритет, до двух меток, прогресс чеклиста, дедлайн, оценка и списание.

## 6. Бэклог и спринты

Список групп: активный спринт, запланированные, бэклог, закрытые.

Карточку переносят между бэклогом и спринтом выбором в строке. Спринт создают, запускают, закрывают и правят имя, цель и даты, пока он не закрыт.

## 7. Roadmap

Одна горизонтальная шкала по дням. Сверху полосы спринтов, ниже полосы карточек, у которых есть начало или дедлайн. Если заполнена одна дата, полоса длиной в день. Задачи без дат перечислены под шкалой.

Шкала берёт самую раннюю и самую позднюю дату и добавляет по два дня. Если диапазон длиннее 120 дней, показывается окно в 120 дней вокруг сегодня. Выходные тише, сегодняшний день отмечен тонкой линией.

## 8. API

Базовый префикс `/api`. Текущий человек передаётся заголовком `X-User-Id`. Ответ об ошибке: `{ "error": "текст" }`.

- `GET /health`
- `GET /meta` — проект, люди, метки, спринты
- `POST /users` — `{ name, email }`
- `GET /issues?scope=active|backlog|all|{sprintId}`
- `POST /issues` — `{ title, type, sprintId }`
- `GET /issues/:id` — карточка целиком
- `PATCH /issues/:id`
- `DELETE /issues/:id`
- `POST /issues/reorder` — `{ status, ids }` в нужном порядке. Смена колонки пишет историю
- `POST /labels` `{ name }`, `DELETE /labels/:id`
- `POST /issues/:id/checklist` `{ title }`
- `PATCH /checklist/:id` `{ title, done }`
- `DELETE /checklist/:id`
- `POST /issues/:id/comments` `{ body }`
- `DELETE /comments/:id`
- `POST /issues/:id/attachments` — `multipart` поле `file`
- `GET /attachments/:id` — файл
- `DELETE /attachments/:id`
- `POST /issues/:id/time` `{ hours, note, loggedAt }`
- `DELETE /time/:id`
- `POST /sprints` `{ name, goal, startDate, endDate }`
- `PATCH /sprints/:id`
- `POST /sprints/:id/start`
- `POST /sprints/:id/close`
- `DELETE /sprints/:id`

Даты в формате `YYYY-MM-DD`. Часы — числа.

## 9. Данные при первом запуске

Если люди ещё не созданы, сервер заполняет проект `TASK` «Наш трекер», шесть человек, метки, три спринта (закрытый, активный, запланированный) и набор карточек, чтобы доска, бэклог и шкала не были пустыми. Повторный запуск существующие данные не затирает. Уже существующий проект с ключом `RKS` переименовывается в `TASK`.

## 10. Вне этой версии

Пароли и сессии, роли, уведомления, несколько проектов, эпики, подзадачи, вики, дашборды, автоматизации, почта, поиск по описанию и по комментариям.
